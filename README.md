# bupo-Link C++ 高性能网络延迟测试工具

一个用于测量家庭/企业网络 Bufferbloat（缓冲膨胀）的跨平台命令行工具，采用 C++ 编写，在 Windows / Linux / Termux 上均可运行。通过 UDP 流量泛洪模拟上行满载，同时以 ICMP（或 TCP）探测延迟变化，精准评估路由器在高负载下的表现。

## 📌 项目特点

### ⚡ 极速发包

采用线程本地聚合计数、CPU 绑核、大发送缓冲区等优化，单机可轻松跑满千兆网卡（约 950 Mbps），充分压榦路由器性能。

### 🎛️ 交互式配置向导

直观的 ASCII 界面菜单，支持选择网卡、设定目标 IP、端口（单/范围）、线程数、测试时长、数据包类型（随机 / 全零 / DNS / NTP / SSDP / 混合）以及高级参数（SO_SNDBUF、Ping 间隔）。

### 📊 实时反馈与统计报告

测试中每 0.5 秒更新当前速率、丢包率、RTT 延迟；停止后自动生成包含最小/最大/平均延迟、抖动（标准差）和总流量的完整报告。

### 🔄 跨平台兼容

通过条件编译支持 Windows（MinGW / MSVC）、Linux 和 Android Termux，同一份代码三端通用。

### 🛑 安全停止

支持 Ctrl + C 即时终止测试，并自动输出统计结果，不会丢失数据。

## 🚀 快速开始

### 1. 编译环境

- Windows：安装 MinGW-w64 或 TDM-GCC，并确保 g++ 已加入 PATH。
- Linux / Termux：安装 build-essential 或 g++（Termux 需执行 `pkg install g++`）。

### 2. 获取源码

将本仓库的 `main.cpp` 下载到本地目录。

### 3. 编译

#### Windows（MinGW）

```bash
g++ -std=c++17 -O2 -march=native main.cpp -o ds_test.exe -pthread -lws2_32 -liphlpapi -lwinmm
```

若出现字符编码警告，可追加：

```bash
g++ -std=c++17 -O2 -march=native main.cpp -o ds_test.exe -pthread -lws2_32 -liphlpapi -lwinmm -finput-charset=UTF-8 -fexec-charset=GBK
```

#### Linux / Termux

```bash
g++ -std=c++17 -O2 -march=native main.cpp -o ds_test -pthread
```

### 4. 运行

必须以管理员 / root 身份运行，以便调整线程优先级和绑定 CPU 核心（Windows 上右键“以管理员身份运行”）。

```bash
# Windows
.\ds_test.exe

# Linux / Termux
sudo ./ds_test
```

## 🧭 使用流程

启动程序后，会自动扫描并显示当前网络环境（系统、主机名、IP、网关、DNS、所有网卡及其 IP / 网关）。

### 选择网卡

输入列表中的编号（如 `5` 选择 VMware VMnet8），程序会将该网卡的网关设为默认目标 IP。

### 基本配置

- 目标 IP：可手动修改
- 端口：单端口如 `53`，或范围如 `1000-2000`
- 线程数：建议 `8~64`，根据 CPU 核心数调整
- 测试时长：`0` 表示无限，按 `Ctrl + C` 停止

### 数据包类型

1. 随机数据（不可压缩，最有效）
2. 全零数据（可被硬件压缩，效果较差）
3. DNS 查询（短包，压路由器 CPU / 会话表）
4. NTP 请求（短包）
5. SSDP 发现（多播短包）
6. 混合模式（随机大包 + DNS + NTP）

### 高级配置

- Socket 发送缓冲区大小（KB），默认 `1024`（1 MB），调大可提高吞吐，但可能隐藏 Bufferbloat。
- Ping 间隔（秒），默认 `0.3`，即每 300 ms 测一次 RTT。

### 确认并启动

按 Enter 开始测试，实时显示速率、丢包、RTT。

### 停止

按 `Ctrl + C` 安全终止，自动输出统计报告，并按任意键返回主菜单。

## 📋 配置参数说明

| 参数 | 说明 | 建议值 |
| --- | --- | --- |
| 目标 IP | 待测试的 IP（通常为网关或公网 DNS） | 自动填充为所选网卡的网关 |
| 端口 | 单端口或范围，UDP 泛洪的目标端口 | 53（DNS）、80、443 或 1-65535 范围 |
| 线程数 | 并发发包线程数 | CPU 核心数 × 2（如 8 核 → 16） |
| 测试时长 | 秒，0 为无限 | 30~60 秒或无限 |
| 数据包类型 | 载荷内容及长度模式 | 1（随机）或 6（混合） |
| SO_SNDBUF | 发送缓冲区大小（KB） | 1024（高性能）或 64（暴露缓冲膨胀） |
| Ping 间隔 | RTT 测量间隔（秒） | 0.1~0.5 |

## 📊 输出报告解读

测试结束后，程序会打印如下统计：

```text
========== 统计报告 ==========
总发送包数: 12345
接收包数:   12000
丢包率:     2.79%
平均速率:   934.56 Mbps
最小延迟:   1.2 ms
最大延迟:   156.3 ms
平均延迟:   23.5 ms
抖动 (std): 18.7 ms
================================
```

- 丢包率：UDP 泛洪下 ICMP / TCP 探测的丢包比例，越高说明路由器处理能力越差。
- 平均速率：实际 UDP 发送吞吐量，接近物理带宽上限则表示程序无瓶颈。
- 延迟增量（未直接显示，可与基准对比）：负载下平均延迟减去空闲时延迟，差值 > 10 ms 即存在明显 Bufferbloat。

## 🛠️ 性能优化机制

- 线程本地聚合：每个线程独立计数，每 64 个包才更新一次全局原子变量，消除缓存争抢。
- CPU 绑核：使用 `SetThreadAffinityMask`（Win）或 `pthread_setaffinity_np`（Linux）固定每个线程到特定核心，提升缓存命中。
- 大发送缓冲区：强制 `SO_SNDBUF` 至少 1 MB，减少 `sendto` 阻塞。
- 短超时：发送超时设为 10 ms，兼顾响应速度与吞吐。

## ⚠️ 注意事项

- 防火墙：Windows 防火墙或杀毒软件可能拦截 UDP 流量，测试前请暂时关闭或添加排除规则。
- 虚拟网卡：VMware / VirtualBox 等虚拟适配器性能较低，建议选择物理网卡（如 WLAN 或以太网）。
- 路由器负载：持续高负载可能导致路由器死机或重启，请确保有备用网络恢复手段。
- 权限：Linux 下需 `sudo` 运行，否则无法调整线程优先级和绑定核心（但基本功能仍可运行）。
- 编码：源码建议保存为 GBK 编码，避免终端乱码；若用 UTF-8，编译时添加 `-finput-charset=UTF-8 -fexec-charset=GBK`。
